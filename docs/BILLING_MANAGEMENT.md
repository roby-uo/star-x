# 人民币与统一费率

## 日常管理

「计费管理」在一页提供两项设置及真实价格目录：

| 上游采购方式 | 售价规则 | 日常设置 |
| --- | --- | --- |
| 按量 API | 人民币采购基准价 × API 售价倍率 | 默认 1.4，可统一调整 |
| 授权账号、包月订阅 | 人民币参考基准价 × 分组倍率 | 选择分组后调整倍率 |

每次只执行一条销售规则，不叠加用户专属、峰时、图片或视频独立销售倍率。供应商的优先处理、长输入、分辨率等基础价格差异仍按实际型号与规格计算。

用户访问本站都使用 API 密钥。上述分类描述**上游采购方式**：使用密钥连接的编程订阅也属于账号参考路线，不能仅根据密钥认证认定为按量采购。

目录来自真实扣费引擎，显示人民币基准价、售价、来源及待确认原因。详细规格和算费预览按需打开，预览不调用模型、不扣费。供应商单价和合同折扣在折叠的「价格来源与特殊供应商」配置；同价模型可共用规则。

## 价格识别范围

系统自动匹配**已维护的价格表**，不会通过模型名或 API Key 获知供应商的合同实付金额。

- 精确匹配供应商站点、地区、上游型号、计费单位、分辨率、质量、处理层级及输入档位。
- 官方人民币模型保持原价；美元基准价固定按 **6.2** 换成人民币。
- 官方参考价、已维护参考价和人工采购基准分别标记。优惠、合同价及第三方上游需要管理员确认。
- 包月实付独立记录，不伪装成准确的单次采购成本。授权账号内部预算倍率保留用于调度与统计，不乘入用户售价。
- 未确认价格、重复采购方案、规格缺项、输入区间重叠或空洞，在付费调用前拒绝，不能请求成功后按零费用处理。
- 新简化模式不猜测额度包或混合采购的单次成本；历史记录可保留核对，先确认并登记明确的按量基准。
- 图片理解、生成图片、视频生成按各自接口与单位计算；文字请求内的图片生成工具保存组合价格快照。

MiniMax 中国站与全球站分别匹配。中国站参考价格根据 [MiniMax 官方价目表](https://platform.minimax.cn/docs/pricing/overview) 维护；DeepSeek、智谱（含 GLM-5.3-FlashX）、Moonshot K2 系列与火山的中国站使用各自人民币参考价，不套用国际美元价。价表日期和已维护规则不代表供应商实时对账。

## 钱包与充值

所有站内页面的金额展示和金额输入统一人民币：

```text
原内部余额 100 → 显示 ¥620，原有权益保留
新支付 ¥100 → 内部入账 100 ÷ 6.2 → 显示到账 ¥100
美元基准价 1 → 人民币基准价 ¥6.2 → API 倍率 1.4 → 售价 ¥8.68
```

内部账本及旧 API 金额字段继续保留 USD 口径；这是统一人民币展示与输入，不是把数据库旧余额数值直接改成人民币。

- 展示内部账本金额时 ×6.2；人民币余额调整、兑换码面额及安全额度输入写入旧 API 前 ÷6.2。
- 新 CNY 支付按实付 ÷6.2 入内部账本；USD 支付按原值入账。额外赠送由独立 `recharge_bonus_multiplier` 管理，默认 1。
- 旧在线充值美元倍率只适用于旧模式，不与新人民币规则叠加。支付配置支持局部保存，调整赠送不会清空支付开关或渠道。
- 历史余额、冻结、已售兑换码、额度和旧订单保留原值；展示按固定比例换算。原始现金支付、退款币种及支付通道金额不更改。
- 外部店铺售出的旧卡密保留原面额权益；新面额按人民币设置并转换内部金额，不自动改外部店铺商品。
- 内部账本、订单额度及相关累计值至少保留 12 位小数，低价 token 与一分钱充值不会因内部换算舍入为零。现金仍按实际支付通道精度处理。
- 固定 6.2 是站内规则，不是供应商实时结汇价格。其他外部支付币种不凭空指定汇率，原交易记录保留原币。

## 订阅与退款

旧订阅商品的 `currency` 曾是展示标签，不能重新解释为真实账币、自动把原人民币售价乘 6.2。

- 旧商品的真实人民币售价按原结账规则计算并返回 `price_cny`，保留原收款金额。
- 新建或明确调整售价时使用 `cash_price_cny`；原价使用 `cash_original_price_cny`。未设置这些字段的旧商品不回填、不自动涨价。
- 商品现金售价与订阅包含的日周月额度分别处理。额度仍按内部账本 ×6.2 展示。
- 新订单记录本次入账规则；回调幂等，重复支付通知不重复加款。
- 退款按原订单现金与内部入账的比例计算；全额退款判断使用内部精度，查询支付通道退款状态使用真实退款金额。

## 价格快照与兼容

真实请求在调用上游前保存不可变价格快照。每笔扣款事务同时保存配置版本、来源、原价、倍率及最终价格依据；快照写入失败时扣款回滚。供应商原币用于溯源，日常页面统一人民币。

视频与批量图片沿用任务创建时冻结的报价；旧已提交任务继续使用旧快照。新的报价绑定实际选中账号，价格变化要求重新确认。WebSocket 每轮使用独立快照，后续调价或请求不能覆盖上一轮账单。

既有 `balance`、`amount`、`*_usd`、额度及销售 API 的原单位保留。新增人民币字段明确命名或带币种，不能静默把旧客户端收到的金额单位改成 CNY。

`simple_billing_enabled` 缺省为启用，默认 API 倍率 1.4；显式关闭保留旧扣费规则供兼容。升级前通过管理端价格目录核对实际已配置账号与型号，补齐待确认的采购基准。

## 用户隐私

用户只需查看可用模型、结果、请求次数、真实 token 和媒体用量。使用记录、密钥用量、仪表盘、图表、CSV、公开密钥查询及模型提示不展示采购成本、售价明细、倍率或利润。人民币余额、充值购买实付和用户自设安全额度仍可查看。

管理员接口与导出保留财务信息。视频校验对用户仅返回不透明 `version`，金额快照由服务器保存，通过 `X-Video-Quote` 校验配置。

兼容路径 `/v1/sub2api/billing` 的版本 2 响应只包含可见性元数据，不返回费率；旧版上游探测不能将未读取费率猜成 1。
