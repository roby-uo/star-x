# 模型服务与用户模型管理设计

日期：2026-09-30

## 2026-09-30 产品流程重设计

本节优先级高于下方历史设计。产品定位为 API 中转站；按用户最新决定，用户端不展示价格与限制面板，不提供“我的视频任务”管理入口。实现与验证范围见本节末尾。

### 问题与产品决定

当前管理员在“已配置模型／对外服务与定价”下面又遇到“模型目录与开放／视频任务与账务”，配置一个模型还要先理解渠道。用户侧按模型与分组重复列行，平台与接口路径占据主列表，价格及能力藏在多个弹窗里。功能具备基础实现，但业务流程没有收敛。

以模型为操作起点：管理员选一个模型完成规格、价格和开放；用户选一个模型完成 API 接入或在线测试。兼容协议和能力一致的模型在目录中聚合，分组差异在详情里选择。对外计费仍由后台配置、分组倍率与服务端校验执行。

### 管理员界面

- **模型服务**：唯一模型目录，保留搜索、全部／文本／图片／视频分类和开放状态筛选。列为模型、供应商、规格与价格摘要、开放分组、状态、配置。移除旧的两层页签与“配置对外服务与定价”跳转。
- **模型详情**：使用独立详情页或宽抽屉，顶部为模型名称、调用名称和保存／发布动作；依次展示“规格与基础售价”“开放分组与实收预览”“上游来源”。模型映射、协议、渠道及路由放入高级配置。第一次配置按此顺序引导，日常修改直接定位对应区块，不强制每次重走向导。编辑前始终明确当前价格覆盖哪些分组；存在多个基础价格范围时先选择范围，再编辑。已开放模型采用“预览并应用”，首次未开放模型允许保存草稿；暂停单独操作，不能将“保存修改草稿”误做成停止现有服务。
- **上游管理**：供应商、账号、模型登记／同步、健康与权限验证。显示供应商 MiniMax，协议标记为技术信息。登记 H3 不等于账号通过视频生成验证。
- **分组与倍率**：沿用当前分组记录，管理倍率与已有资源分配；模型详情只引用倍率，不再维护第二个倍率。当前分组兼任资源池与客户权限，首期不拆成两套数据实体。
- **任务中心**：管理员独立运营入口，处理视频任务及相关结算状态。提供分页和本页用户／模型／编号／状态筛选。文本与图像用量仍在使用记录查看。

每个模型的价格只有一个编辑位置。文本、图片从同一详情编辑已有价格记录，H3 从规格表编辑每秒价。界面可以隐藏渠道概念，实际更新必须解析并保留现有渠道、分组与价格映射；多个渠道价格不同则先选授权范围，不能悄悄覆盖所有渠道。

### 用户界面

- **模型目录**：全部／文本／图像／视频分类，使用卡片展示模型名、模型家族和能力。同协议模型跨分组合并；不显示价格、上游账号、接口路径或重复分组行。
- **模型详情**：同一窗口提供“API 接入／在线测试”。先选择调用分组和已有密钥；单一密钥自动选择，没有密钥时提供创建入口。切换分组重新载入对应密钥，过期的异步响应不会覆盖新的选择。
- **API 接入**：展示服务地址、模型名称、接口和完整示例。复制内容使用占位密钥，不复制真实密钥。H3 示例包含报价版本、幂等创建与任务查询。
- **在线测试**：文本、图像和 H3 在当前详情内发送测试请求。参数使用所选分组与密钥实际允许的规格。提交前明确确认“在线测试会消耗账户额度”，不显示价格／倍率面板；H3 所需报价凭证由内部获取并校验。当前视频测试显示任务编号、状态和安全结果链接，状态查询不会创建新任务。
- **视频查询**：用户应用通过 API 保存任务编号并查询结果。删除独立用户任务管理入口；后台持久化记录、结算与管理员核对继续保留。不确定提交保留编号并阻止自动重提，关闭测试窗口停止页面轮询。
- **API 密钥**：用途、所属分组、额度与权限限制。高级模型／视频规格限制按需展开，密钥只收窄分组授权，不扩大权限。

聚合同一模型时不能合并实际不兼容的调用：稳定身份包含对外调用名称和协议能力；同名但请求结构或语义不同则单独展示并加供应商／协议标记。不要仅按字符串模型名聚合。

### H3 操作示例

管理员：添加 MiniMax 账号 → 登记 H3 → 在模型服务打开 H3 → 设置 768P／2K 每秒基础价 → 普通组开放 768P、4–5 秒，VIP 开放 768P／2K、4–15 秒 → 查看各组实收费 → 发布。

用户：目录选择 H3 → 选择分组和调用密钥 → 复制创建／查询示例接入自己的应用；需要在线测试时选择允许规格 → 确认消耗额度 → 提交 → 在当前窗口查询结果。应用侧自行保存任务编号。

示例基础价为 768P $0.08／秒、2K $0.13／秒，普通组倍率 1.4、VIP 倍率 1。示例 5 秒 768P 分别为 $0.56 与 $0.40，仅用于说明设计，不代表线上配置或供应商采购成本。

### 实施边界与验收

1. 已实现入口收敛：管理端单一模型目录，统一规格／基础售价／开放配置，独立分组倍率和管理员任务中心；用户卡片目录和统一接入／测试详情。
2. 已实现修改范围与确认：编辑前明确基础价格覆盖的分组，应用前确认影响；已发布模型保持发布，暂停独立操作。共享模型价格记录拆分目标模型，保留其他模型、协议、渠道配置和已存在的分档价格；从服务器重读后发现目标配置变化时要求重新确认。
3. 已实现规格表单和调用示例；H3 页面状态查询只查询本次测试。复杂通配价格、模型映射与路由仍通过高级渠道配置维护。尚未提供全局任务检索、成本利润管理或独立配置版本。
4. 既有无策略模型显示“已开放 · 沿用现有配置”，不能统一当作待开放或迁移为草稿，避免中断正常服务。
5. 管理员价格显示计费单位，未知价格不显示零价。用户不显示价格面板；服务端仍按实际配置结算，视频报价绑定所选密钥与规格，改价／改规格后旧报价失效。
6. 目录合并后仍验证各分组的有效规格、倍率、密钥限制和任务归属。关闭用户任务界面不删除持久化数据和任务查询 API。
7. 设计稿的发布、生成、余额和状态仅作交互演示；真实 MiniMax 付费验证仍待用户配置授权账号，未经验证不显示视频权限已验证。
8. 目录能力摘要和实收预览必须来自有效规格。关闭 2K 后摘要不再显示 2K；最长仅 4 秒的组使用 4 秒示例，不能预览该组无权调用的 5 秒组合。

## 1. 目标与现状

让管理员明确控制“接入什么模型、开放什么规格、给谁使用、收多少钱”，让用户明确看到“我能用什么、如何选择、这次多少钱、生成到哪一步”。沿用现有四个导航入口，避免把同一个模型分散在多个相互独立的配置页。

设计前代码已确认的现状（历史背景）：

- 上游账号支持 MiniMax-H3 白名单与原生视频创建、查询接口；模型登记不等于验证该密钥具备视频权限。
- 当前公开接入支持 H3 的文本及首尾帧输入、768P/2K、4–15 秒；不包含 H3-Max 和参考视频、参考音频等完整官方能力。
- H3 当前复用图片生成权限；模型用户页没有视频测试及规格表单。
- H3 当前使用内置按秒价格和倍率计算，尚未接入可编辑的服务规格价格矩阵。
- 创建任务被上游接受时记账；后续失败没有完整自动退款流程。任务归属绑定尚不能替代持久化任务与账务记录。

## 2. 四个入口的职责

| 入口 | 负责的事情 | 主要页面 |
| --- | --- | --- |
| 管理端／上游管理 | 供应商账号、密钥、接口适配、模型来源、健康与可用容量 | 账号列表、账号详情、支持模型、连接检查 |
| 管理端／模型服务 | 对外模型目录、开放规格、用户组权限、售价、路由、任务运营 | 模型列表、服务详情、任务记录 |
| 用户端／API 密钥管理 | 应用访问凭据、所属分组、权限收窄、额度和调用限制 | 密钥列表、权限与额度、使用记录 |
| 用户端／模型管理 | 当前身份可用模型、规格与实际价格、生成任务、调用示例 | 可用模型、模型详情、我的任务 |

“已配置模型”和“对外服务与定价”合并为一个模型服务工作区。列表用状态区分“已接入待开放、已发布、暂停服务”，点进模型详情完成规格、价格和开放配置。上游独有但尚未公开的模型仅管理员可见。

## 3. 管理员业务流程

### 3.1 接入账号

账号表单明确区分供应商与接口适配：供应商选择 MiniMax；显示该账号可使用的文本兼容接口及原生视频接口。底层可沿用现有账号结构，但界面不再让管理员以为选择 OpenAI 后只能调用语言模型。

模型来源标记为“上游同步”“平台预设”“手动添加”；验证状态独立显示“未验证、验证通过、验证失败”。同步接口未返回 H3 时允许从预设登记，不能把预设当成该账号已获授权。检查连接与付费生成测试分开操作，并明确测试费用。

### 3.2 配置一个模型服务

模型服务列表：对外名称、模型类型、供应商、发布状态、开放分组、可用规格摘要、售价摘要、可用上游数、最近错误。

详情分为五个页签：

1. 基本信息：名称、简介、类型、调用名称、草稿／发布／暂停状态。
2. 能力与规格：系统已实现的输入模式、分辨率、时长、画幅及有效组合；管理员勾选开放子集并设置默认值。
3. 定价：计费单位、规格基础售价、币种、价格版本；管理员另行维护上游成本，不向用户暴露成本与利润。
4. 开放与路由：可用分组、各组允许的规格、已有倍率摘要、上游账号池、优先级与并发限制。
5. 任务与用量：成功率、耗时、错误、用户任务、计费与退款状态。

发布前校验：至少存在匹配上游；每种开放组合都有价格；默认规格合法；分组允许的能力不能超出适配器支持范围。缺失价格的组合禁止发布，不能自动按零元处理。

### 3.3 H3 的配置示例

以下仅为建议示例，不是当前线上设置：

| 项目 | 普通用户组 | VIP 用户组 |
| --- | --- | --- |
| 分辨率 | 768P | 768P、2K |
| 时长 | 4–5 秒 | 4–15 秒 |
| 输入 | 文生视频、首帧图生视频 | 文生视频、首帧／首尾帧视频 |
| 倍率 | 沿用现有普通组配置 | 沿用现有 VIP 组配置 |

目录中展示一个 MiniMax-H3；分辨率和时长是可选参数，不把每个组合伪装成独立模型。H3-Max 是另一模型，只有单独适配、计费和验证后才能开放。

## 4. 用户侧业务流程

### 4.1 模型管理

模型列表支持全部／文本／图片／视频筛选，首期不展示音频类型。每张卡片展示用户可用的规格摘要、实际单价、调用名称和当前可用状态。同一模型在不同分组下有不同价格时，详情先选择调用分组或对应 API 密钥，避免展示错误价格。

模型详情包含“在线生成、API 调用、价格与限制”。视频生成表单按顺序提供：

1. 调用身份：选定有权限的 API 密钥；单一选择时自动填入。页面会话不能绕过该密钥的限额。
2. 生成方式：文生视频、首帧、首尾帧；仅显示已开放方式。
3. 输入：提示词及对应图片上传。
4. 规格：分辨率、时长、画幅；只允许有效组合。由输入图决定画幅的模式显示“跟随输入图”，不提供会被忽略的选项。
5. 费用区：本次规格、有效单价、预计总价、余额及计费说明；参数变化即时重新报价。
6. 提交：按钮显示“生成视频 · 预计扣费 ¥／$ X”，避免点击后才获知成本。

“我的任务”展示排队、生成中、成功、失败、取消等上游实际支持的状态。可查看输入参数、费用、错误原因、结果预览和下载。仅在上游支持时展示取消。重新生成明确为新任务及新费用，不自动重试可能重复收费的创建请求。下载有效期与任务记录保留期限分别说明。

### 4.2 API 密钥管理

保留现有分组绑定方式。在分组授权范围内，允许用户进一步限制模型、视频规格、消费额度、有效期、速率和并发。密钥只能收窄权限，不能扩大所属分组权限。密钥详情直接链接可用模型和对应调用示例。

任务归属记录用户、密钥、分组与服务。用户通过登录态查看自己创建的历史任务，即使原密钥已删除也保留历史；API 查询继续执行明确的所有权校验，不允许猜测任务编号读取他人结果。

## 5. 分组倍率与模型售价

保留分组倍率这个已有操作习惯。模型服务负责“某规格的基础售价”，分组负责“这个人按什么倍率付费”。两个入口编辑不同数据，彼此链接并显示最终结果，不重复保存相同价格。

简单输出按秒计价时：用户费用 = 规格基础每秒售价 × 时长 × 数量 × 有效倍率。

有效倍率沿用现有用户专属分组覆盖、分组倍率及独立视频倍率的实际优先级，迁移前用现有代码确认所有分支。峰时等规则也由统一报价函数处理，界面显示本次实际采用的规则，不能把多个互斥倍率重复相乘。

例如管理员自行设置 768P 为 $0.08／秒、2K 为 $0.13／秒，用户有效倍率为 1.4，则 768P 的 5 秒视频是 $0.56。这是配置演示，不是对供应商当前成本的承诺。未来参考素材计费单独建费用项，计费未实现前不开放对应输入。

报价附带币种、价格版本、有效期与规格摘要。提交时重新校验；价格已变化则要求客户端刷新报价，不能按未展示的新价格直接扣款。已受理任务保留价格快照，后续改价不影响历史账单。

## 6. 后端约束与任务账务

前端选项、API 校验和计费必须使用同一份有效能力配置。实际可用范围为：适配器已实现能力 ∩ 服务已发布能力 ∩ 分组授权 ∩ 密钥限制 ∩ 可路由账号能力。手工调用 API 也执行同样的校验；禁止仅靠隐藏选项控制权限。

新增视频独立权限，逐步替代复用图片权限。每项能力使用组合约束表达，避免允许分辨率与时长后误以为所有组合都有效。

任务持久化保存：内部任务 ID、上游任务 ID、用户／密钥／分组、服务与上游账号、请求规格、价格快照、状态、结果有效期和计费状态。敏感输入与结果按既定保留策略清理；日志不记录密钥。

提交前原子预占额度，并用幂等键防止重复点击扣费。提交超时且无法确认上游是否已受理时进入待核对状态，不直接重发创建请求。后台查询更新状态，账务只结算一次。失败、取消及超时如何释放额度，必须依据供应商真实计费规则定义；不能假定所有失败任务免费。需要人工处理的差异进入管理员对账列表。

已提交任务查询绑定原上游账号，不能因为路由调整而查询另一账号。暂停服务阻止新建任务，已有任务继续查询与结算。供应商或账号额度、并发不足时明确返回暂不可用。

## 7. 数据与接口边界

逻辑实体包括：上游账号、模型能力定义、对外模型服务、分组服务规则、规格价格、用户任务、任务账务记录。优先复用现有 Channel、分组和价格结构，不为相同职责建立第二套独立配置。

现有接口保持兼容。新增或扩展的接口能力应覆盖：管理员读取／保存／发布服务；用户查询有效模型与规格；生成报价；创建任务；查询任务及历史。具体路由名和数据库迁移在实施时确定。

用户响应只返回有效授权、对外售价及调用需要的数据；不返回上游密钥、路由细节和成本。管理端写配置需审计，记录操作者、前后差异和价格版本。

## 8. 实施顺序与验收

第一阶段：统一模型服务入口；实现 H3 规格与价格矩阵、分组开放规则、视频独立权限、服务端校验；让用户模型详情展示实际可用规格与最终价格。

第二阶段：完成用户生成表单、持久化任务、幂等提交、额度预占与结算、任务历史和管理员排错，构成可正式开放的视频业务闭环。

第三阶段：在真实授权账号验证后，扩展更多供应商、H3-Max 或参考素材模式；每项能力同时交付参数校验、计费、前端选择与错误处理。

迁移时导入既有账号模型、组权限和价格，保留已有文本／图片调用行为。现有服务不能因为新“发布”标记缺失而突然不可用；新能力默认不自动开放。上线前提供旧配置与新有效配置差异预览，对 H3 的权限迁移明确展示受影响分组。

必要验收：

- 普通用户通过页面和直接 API 都无法绕过 2K／时长限制。
- 同一请求的页面报价、API 报价与最终账单一致；组倍率仍生效且不重复计算。
- 重复提交、上游响应丢失、重启与重复状态通知不会重复收费或丢任务。
- 创建成功后发生失败能够按既定规则结算或释放额度，异常可追溯。
- 非所有者不能查询结果；删除密钥、暂停服务、调整价格不破坏已有任务历史。
- 管理员开放规格后用户可见；关闭规格立即约束新请求；原文本／图片服务回归通过。
- 完成真实 MiniMax 付费生成、查询、结果下载与账单核对后，才标记端到端验证通过。此前用户选择稍后自行配置密钥，当前不能声称已完成该验证。
